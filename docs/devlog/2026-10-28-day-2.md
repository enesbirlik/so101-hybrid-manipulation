# Day 2 — Fisheye calibration of the wrist camera

**Date:** 2026-10-28 · **Roadmap step:** 3. Calibration, URDF matching, fisheye camera calibration · **Status:** camera intrinsics done, hand-eye next

The wrist camera has a 135° lens. To measure anything in its images, such as an object's position, we first need its intrinsic parameters:
- the focal length,
- the optical centre,
- the lens distortion.

A lens this wide needs the fisheye (equidistant) model rather than the usual pinhole model.

## What I did

- Printed a 7×5 ChArUco board (DICT_6X6_250, from calibrx.io). Every corner has an ID, so a partly visible board still counts, which makes it much easier to cover the image edges.
  - Checked the print scale with calipers: the 50 mm reference bar measured 48 mm, so the print is at 96 %. That gives 24 mm squares, not the nominal 25 mm.
  - Checked that the board layout matches OpenCV's own `CharucoBoard`. A homography fit of the detected markers gives a 0.6 px error for 7×5 and 575 px for 5×7.
- Wrote [`tools/so101_camera_calib.py`](../../tools/so101_camera_calib.py) with three commands:
  - `capture`: live view with the detected corners and a map of corners saved so far.
  - `calibrate`: `cv2.fisheye.calibrate`, dropping outlier frames.
  - `view`: raw and undistorted image side by side.

  The script uses the OpenCV 4.6 aruco API, which has no `CharucoDetector` yet.
- Ran a first calibration at 1280×960, then a second at 1280×720 with the image rotated upright.

## What I learned

- **Not every resolution shows the whole sensor.** The first calibration (1280×960) gave the optical centre 175 px right of the image centre and only about 80° of horizontal view, and the gripper appeared off to one side. I mapped each mode onto the 4K frame using the board corners:

  | Modes | Part of the 3840×2160 sensor |
  |---|---|
  | 16:9 (1280×720, 1920×1080, 3840×2160) | whole sensor, centred |
  | 4:3 (640×480 … 2592×1944) | the same off-centre crop, x = 78…2958 |

  All modes run at 30 fps at most, so 720p gives the full, centred view at no cost.
- **Mounting matters.** The camera is mounted upside down and has no hardware flip control, so frames are rotated 180° in software as they are read. A 180° rotation keeps fx, fy and k1..k4, but moves the optical centre to (W−1−cx, H−1−cy). Calibration and the ROS driver must therefore use the same orientation.
- **Measure, don't eyeball.** My first reading of a side-by-side screenshot was that 1280×960 was zoomed in and 1600×1200 showed the full sensor. That was wrong, and mapping the corners showed it.
- **RMS alone is not enough.** Two more checks were needed:
  - **Coverage:** the first run had no corners in one image corner, and the model extrapolated nonsense there.
  - **Stability:** I split the frames into two halves and calibrated each separately to see how much the parameters move.

## Result

1280×720, rotated upright, 40 frames:

| | Value |
|---|---|
| RMS reprojection error | 0.71 px (0.33–0.91 per frame, no outliers) |
| fx, fy | 734.4, 736.7 px |
| cx, cy | 642.6, 323.4 px |
| k1..k4 | −0.098, 0.014, −0.013, 0.004 |
| Field of view | 109° horizontal, 57° vertical, 130° diagonal |
| Split-half spread | ~3 px at the centre, ≤ 12 px in the extreme corners (≈ 1 mm at 30 cm) |

The vertical optical centre is 36 px above the image centre. This is a property of the lens, not a fitting error. The independent 1280×960 calibration, mapped to the same frame, puts it at the same place: f = 732, cx = 641.7, cy = 327.5.

Output: [`so101_perception/config/wrist_camera_fisheye.yaml`](../../so101_perception/config/wrist_camera_fisheye.yaml), in ROS `camera_info` format (`distortion_model: equidistant`).

## Problems & fixes

| Problem | Cause | Fix |
|---|---|---|
| Printed squares 24 mm instead of 25 mm | Printer scaled the page to 96 % | Measured, passed `--square-mm 24` (default) |
| Optical centre 175 px off, ~80° view, gripper off-centre | All 4:3 modes are an off-centre sensor crop | Use 1280×720 (full sensor, centred) |
| Image upside down | Camera mounted upside down, no hardware flip | Rotate 180° as frames are read |
